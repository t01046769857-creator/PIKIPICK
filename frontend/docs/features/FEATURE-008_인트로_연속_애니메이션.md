# 피키 인트로 연속 애니메이션

- 상태: 개발 중
- 작성일: 2026-11-12
- 관련 파일: `src/components/PikiIntroScene.tsx`, `src/styles.css`

## 변경 목적

빼꼼, 발견, 다가오기, 손 내밀기가 장면별 슬라이드처럼 보이지 않도록 이동·표정·손 동작의 책임을 분리하고 하나의 상태 흐름으로 연결한다.

## 상태 흐름과 시간

`PEEK (0.7초) → LOOK (0.8초) → NOTICE (0.5초) → APPROACH (1.35초) → REACH (0.7초) → IDLE`

- `PEEK`: 화면 오른쪽 끝의 전용 빼꼼 PNG가 살짝 나타난다.
- `LOOK`: 같은 PNG에서 고개를 가볍게 기울이고 한 번 깜빡인다.
- `NOTICE`: 놀란 표정 프레임으로 짧게 전환한다.
- `APPROACH`: 부모 컨테이너의 연속적인 transform 이동과 자식의 두 번 점프 애니메이션을 결합해 중앙으로 다가온다.
- `REACH`: 안정된 본체+왼쪽 큰 손 레이어를 같은 캔버스에서 교차 전환한다.
- `IDLE`: 말풍선과 손 안내를 보이며 입력을 기다린다.

## 구현 방식과 이유

- 필요한 PNG를 사전 로드하고 `decode()`가 끝난 뒤에만 상태 타이머를 시작한다.
- 장면 전체를 재마운트하지 않고, `intro-v2-motion`이라는 지속 컨테이너를 유지한다.
- 빼꼼 위치 변수는 `PEEK` 선택자 안이 아니라 지속 컨테이너에 둔다. 이전 구조에서는 `LOOK`가 같은 변수를 참조했지만 변수가 더 이상 상속되지 않아 transform이 무효화되고 중앙으로 튈 수 있었다.
- 본체의 이동, 점프/착지 탄성, 마지막 손 강조를 서로 다른 레이어에서 처리해 한 transform이 다른 transform을 덮어쓰지 않게 한다.
- 시작 입력은 보는 사람 기준 왼쪽의 큰 손과 동일한 좌표계의 투명 버튼만 사용한다. 안내 문구는 클릭 버튼이 아니다.

### PEEK 첫 프레임 정렬

- PEEK의 초기 CSS transform과 기존 keyframe 0%가 서로 다른 x 좌표를 사용해 첫 프레임이 잠깐 어긋날 수 있었다.
- PEEK/LOOK 컨테이너는 이제 `position: absolute; right: 0; bottom: 0`으로 고정한다. PNG의 오른쪽 직선 경계가 첫 렌더부터 화면 오른쪽 경계와 일치한다.
- PEEK keyframe은 x축 이동을 하지 않는다. 0%, 중간, 100% 모두 `translateX(0)`에 해당하는 변환을 사용하며, 세로의 매우 작은 움직임과 투명도만 바뀐다.

## 영향 범위

인트로 컴포넌트와 인트로 전용 CSS만 수정한다. 로고, 놀이터 배경, 소리 버튼, 게임 규칙, 기록 및 별 보상은 변경하지 않는다.

## 검증

이 작업 환경에는 Node/Vite와 브라우저 실행 도구가 없어 장면별 실제 재생 및 스크린샷 검증은 수행하지 못했다. 소스 정적 점검과 `git diff --check`만 수행했다. 인트로는 아직 최종 Before/After 완료 상태가 아니다.
