# 비밀나라 피키 걷기 발 끌림 진단 및 보정

## 목적

비밀나라 평지·무지개 다리 구간에서 피키가 발을 끌며 미끄러지는 것처럼 보이는 원인을 확인하고, 경로·카메라·이동 속도·원본 걷기 PNG를 변경하지 않는 범위에서 렌더링 기준을 보정했다.

## 확인 결과

- 사용자 영상 `C:\Users\mbc\Downloads\녹음 2026-11-19 125002.mp4`는 852×464, 30fps, 약 18.7초였다.
- 현재 걷기 프레임은 좌우 각각 4장씩, 총 8장이다. 모든 prepared PNG는 1254×1254 RGBA 캔버스이며 하단 기준선은 y=1198로 정규화되어 있다.
- 이동 속도는 100px/s이고 `ADVENTURE_WALK_FRAME_DISTANCE=20`이므로 0.2초마다 프레임이 바뀌며 4프레임 주기는 0.8초(5fps)다. 이 주기 자체는 속도와 일치한다.
- 그러나 프레임 내부의 지지 발 x가 방향별로 크게 바뀐다. 왼쪽은 487, 438, 413, 684px, 오른쪽은 778, 685, 789, 498px이다. 또한 v2 `manifest.json`은 해당 자료를 `review_only_not_approved_for_game`로 표시하고, README도 실제 보행 동작을 보장하지 않는다고 안내한다. 시각적으로도 각 방향의 1~3 프레임은 같은 지지 발 계열이 반복되고 4프레임에서 반대 발로 전환된다.

## 적용한 최소 보정

`LxpSecretLandDashboard.tsx`에서 이동 중 스프라이트의 렌더링 기준을 각 프레임의 가변 발 x가 아니라 공통 캔버스 중심 `(627 / 1254, 1198 / 1254)`으로 분리했다. 실제 측정 발 기준(`footAnchor`)은 디버그·접지 진단용으로 유지한다.

`LxpSecretLandDashboard.css`의 활성 월드 캐릭터 transform은 이동 중 `--render-anchor-x/y`를 사용하도록 정리했다. 이 변경은 몸통·가방이 프레임 교체 때 좌우로 튀는 현상을 줄이며, 경로 노드·카메라·100px/s·배경·저장/해금 로직은 변경하지 않는다.

## 브라우저 검증

검증 서버는 다른 포트가 점유되어 `http://127.0.0.1:5175/play/world`를 사용했다. 1440×900에서 평지와 다리의 정지·이동·정지를 캡처했고, 390×844에서도 다리 이동 화면을 확인했다.

- 1440×900: 방향 전환 후 좌우 프레임이 표시되고, 이동 중 캐릭터 중심은 안정적이었다. 다리 데크 위의 위치도 확인했다.
- 390×844: 다리 화면에서 캐릭터와 데크가 함께 표시되며 문서 가로 스크롤은 없었다.
- 디버그 측정: 다리 우측에서 왼쪽으로 이동할 때 실제 발 마커의 화면 오차가 프레임별로 약 -18.4px~+4.9px 변했다. 따라서 공통 렌더 기준 보정만으로 발 끌림을 완전히 해결했다고 판정하지 않는다.

## 남은 문제

현재 8개 PNG의 발 포즈·프레임 순서가 완전한 교차 보행 사이클이 아니므로 CSS bounce, 회전, 임의 보정으로 숨기지 않았다. 완전한 해결에는 좌우 각각 `contact → pass → contact → pass`가 명확한 4프레임 이상과 공통 몸통 기준을 가진 새 걷기 에셋이 필요하다. 새 에셋이 준비되기 전까지는 현재 보정 상태를 유지하고, 기존 PNG 원본·이동 속도·경로·카메라를 추가 변경하지 않는다.
