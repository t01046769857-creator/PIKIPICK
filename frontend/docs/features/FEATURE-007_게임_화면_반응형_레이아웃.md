# FEATURE-007 — 게임 화면 반응형 레이아웃

- 문서 목적: 인트로 이후 화면의 헤더·별 보상판·피키·선택 버튼 배치를 안정화한 방식을 설명합니다.
- 관련 기능: 모드 선택, 규칙 안내, 준비, 가위바위보 진행, 결과 피드백
- 현재 상태: 구현됨·미검증
- 마지막 확인일: 2026-11-12
- 관련 코드 위치: [`App.tsx`](../../src/App.tsx), [`styles.css`](../../src/styles.css)
- 관련 문서: [개발 현황](../DEVELOPMENT_STATUS.md) · [FEATURE-003](FEATURE-003_별_보상과_누적_기록.md)

## 기존 문제

`styles.css`에 과거 게임 레이아웃 규칙이 여러 구간에 중복되어 있었습니다. 같은 `.play-card--game`, `.game-panel`, `.stars` 규칙과 여러 모바일 미디어 쿼리가 서로 크기·고정 높이를 덮었습니다. 또한 기본 모바일 `.topbar`가 세로 Flex로 바뀌어 별 보상판이 제목 아래로 내려갈 수 있었습니다.

## 현재 구조

`App.tsx`는 인트로가 아닌 모든 화면의 최상위 요소에 `app-shell--game-flow`를 추가합니다.

```tsx
<main className={`app-shell app-shell--game-flow ${gameScreen ? 'app-shell--game' : ''}`}>
```

- `app-shell--game-flow`: 모드 선택·규칙·준비·게임 진행에 공통 적용
- `app-shell--game`: 실제 가위바위보 진행/결과 화면에만 추가 적용
- 인트로는 `PikiIntroScene`을 바로 반환하므로 이 클래스를 사용하지 않습니다.

게임 흐름 헤더는 `minmax(0, 1fr) auto` 두 열 Grid입니다. 왼쪽에는 로고·게임 제목, 오른쪽에는 별 보상판과 게임 메뉴가 있으며, 좁은 화면에서도 별 보상판이 아래로 떨어지는 대신 오른쪽 열 안에서 축소됩니다.

## 변경한 CSS 원칙

1. 고정 `height` 대신 게임 보드에 유연한 `min-height`와 `height: auto`를 사용합니다.
2. 피키 영역과 선택 버튼의 높이를 `vh` 기반 `clamp()`로 조정합니다.
3. 640px 이하에서는 별 보상판·피키·버튼만 필요한 범위에서 축소합니다.
4. 375×667처럼 짧은 화면에서는 터치 버튼을 과도하게 축소하지 않고 최소 세로 스크롤을 허용합니다.

## 영향 범위와 검증

- 변경 대상은 `App.tsx`의 게임 흐름 className과 게임 전용 CSS입니다.
- 인트로 `PikiIntroScene`, 인트로 배경·로고 위치·손 클릭 영역·게임 규칙·별 계산 로직은 변경하지 않았습니다.
- `git diff --check`로 정적 변경 형식을 확인해야 합니다.
- 현재 환경에는 Node/Vite 브라우저 실행 환경이 없어 375×667, 390×844, 768×1024, 1366×768, 1440×900, 1920×1080 실화면 검증은 아직 수행하지 못했습니다.
